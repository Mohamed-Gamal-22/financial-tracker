## ⚠️ تحديث مهم عن الكولكشن الجديد

في الكولكشن القديم كان فيه 4 endpoints للكاتيجوري (إنشاء، إنشاء دفعة، حذف، عرض). **في الكولكشن الجديد ده، اتنقلوا 3 منهم (إنشاء، إنشاء دفعة، حذف) لقسم منفصل اسمه `Admin`**، وبقى فولدر الـ Category العادي فيه **endpoint واحد بس**:

---

## عرض كل التصنيفات

`GET /category`

**Header:** `authorization: <access_token>`

**Response (نجاح):**
```json
{
  "message": "Done",
  "success": true,
  "status": 200,
  "data": [
    { "_id": "6a7b2544b7e711374175c0a6", "name": "راتب أساسي", "type": "income" },
    { "_id": "6a7b2544b7e711374175c0a8", "name": "طعام ومشروبات", "type": "expense" },
    { "_id": "6a7b2544b7e711374175c0a9", "name": "سكن وإيجار", "type": "expense" },
    { "_id": "6a7b2544b7e711374175c0ad", "name": "ادخار للسفر", "type": "savings" }
  ]
}
```

| الحقل | النوع | الوصف |
| --- | --- | --- |
| _id | string | معرّف التصنيف — يُستخدم لاحقًا كـ reference عند إضافة معاملة |
| name | string | اسم التصنيف |
| type | string | نوع التصنيف — واحد من 3 قيم: `income` (دخل) / `expense` (مصروف) / `savings` (ادخار) |

---

## ملاحظات للأجنت

- هنا فقط **قراءة** (GET) — التصنيفات ثابتة من الباك إند والمستخدم العادي **مش بيقدر يضيف أو يحذف تصنيف**. أي واجهة إضافة/حذف تصنيف من داخل التطبيق (لو كانت متصممة قبل كده) لازم تتشال من نطاق شاشات المستخدم العادي.
- استدعي الـ endpoint ده مرة واحدة وخزّن النتيجة (Context/State أو Cache) بدل ما تستدعيه في كل شاشة فيها اختيار تصنيف، لأن الداتا شبه ثابتة.
- الـ `type` استخدميه زي ما هو بالظبط (حروف إنجليزي صغيرة: `income`/`expense`/`savings`) لو هتعملي فلترة أو تلوين حسب النوع.
